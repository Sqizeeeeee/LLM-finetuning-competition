# notes_pre — 01_bradley_terry_deberta_base

## Задача
Kaggle-соревнование LMSYS Chatbot Arena: предсказать, какой из двух ответов LLM (A или B) предпочтёт судья, либо ничью (`winner_model_a` / `winner_model_b` / `winner_tie`).

## Подход
Bradley-Terry reward model, Variant A (обучаемый порог δ):
- Один энкодер с общими весами считает скалярную награду `r` для (промпт + ответ A) и отдельно для (промпт + ответ B).
- `d = r_a - r_b`
- `P(a wins) = sigmoid(d - δ)`, `P(b wins) = sigmoid(-d - δ)`, `P(tie) = 1 - P(a) - P(b)`
- δ — `nn.Parameter`, обучается вместе с энкодером через backprop
- Лосс: стандартный 3-классовый cross-entropy (не MarginRankingLoss)

Вариант с отдельным параметром ν (Bradley-Terry-Davidson) сознательно отложен: сначала обучаем Variant A, затем пост-анализ покажет, добавил бы ν что-то значимое.

## Цель этого эксперимента
Этап 1 из двухэтапного плана: получить опорный (baseline) скор на DeBERTa-v3-base, обученный на CUDA (Kaggle Notebooks), без попыток выжать максимум качества. Дальше на Modal.com будем пробовать апгрейды (больший/другой энкодер, ансамбль по фолдам) и сравнивать с этим скором.

## Энкодер и конфиг
- Backbone: `microsoft/deberta-v3-base` (~184M параметров)
- Пулинг: CLS (опция mean также реализована в `RewardModel`)
- `max_length = 1024`
- Паддинг: обычный (без динамического паддинга и группировки по длине — не требуется, памяти на CUDA достаточно для базовой модели)
- batch_size, lr, epochs — см. `config.yaml`

## Данные
- Источник: `data/raw/train.csv` → `preprocessing/common.py` → `data/processed/common/train_clean.parquet` → `data/processed/BT/train_bt.parquet`
- Парсинг списков-раундов через `json.loads` (не `literal_eval` — падал на `null`, портил 142 строки, см. `parsing_notes.md`)
- Пропущенные/пустые раунды заменены заглушкой `[EMPTY]`, строки не выбрасываются
- Дедупликация полных дублей (одинаковый вход и одинаковая метка) на уровне `common.py`
- Разбиение на фолды: GroupKFold по `prompt`, 5 фолдов — исключает утечку одинаковых промптов между train/val

## Железо и окружение
- Kaggle Notebooks, GPU T4/P100 (CUDA), лимит 30 ч/неделю
- FA2 и bf16 недоступны на этом железе (до-Ampere) — используем fp16 или fp32
- Одна GPU (не задействуем вторую T4 при T4×2, чтобы не усложнять код под multi-GPU)

## Рабочий процесс
1. Исходники эксперимента пишутся по файлам в репозитории (конфиг, dataset, модель, train-скрипт)
2. Из них собирается единый ноутбук для Kaggle
3. Обучение запускается на Kaggle
4. Выполненный ноутбук скачивается и кладётся в папку эксперимента как воспроизводимый артефакт
5. Инференс-ноутбук собирается отдельно, после того как есть обученные веса

## Метрика
Log loss по трём классам (согласно правилам соревнования), считается на OOF-предсказаниях по GroupKFold.
