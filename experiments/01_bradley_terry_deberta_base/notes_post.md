# DeBERTa-v3-base + Bradley–Terry — разбор результата

Сабмит **v6** получил public log loss **1.26893**. В [локальном логе](res/metrics_history.csv) средний log loss по пяти фолдам снизился с **1.4674** на первой эпохе до **1.2613** на четвёртой. Все фолды одинакового размера. Точный состав весов опубликованной версии по локальным файлам не сверяли. См. [таблицу сабмитов](../../README.md) и [локальный ноутбук инференса](../../submissions/exp1/llm-finetuning-bt-deberta.ipynb).

## Как обучалась модель

[Kaggle-ноутбук](notebooks/kaggle.ipynb) использует общий DeBERTa-энкодер для пар «промпт + ответ A/B». Разность скалярных наград определяет предпочтение A/B, а обучаемый порог δ задаёт вероятность ничьей. В сохранённом коде пять фолдов (0–4), четыре эпохи, CLS-пулинг, предел 1024 токена и fp16. Learning rate энкодера, головы и δ составляют соответственно `5e-5`, `1e-4` и `2e-5`. В [истории проблем](problems.md) для отдельной группы δ предложено `2e-6`. Локальная копия Kaggle-ноутбука без логов обучения.

В ноутбуке задан resume из `checkpoint1/res`. Для завершённых фолдов он использует уже сохранённые веса, а для продолжаемого фолда восстанавливает состояние оптимизатора и scheduler. Поэтому по ячейке `CONFIG` нельзя восстановить фактическую историю learning rate каждого из пяти весов.

## Почему log loss остался высоким

**Порог ничьей остался слишком маленьким.** Напрямую из пяти `best.pt` получаем `δ` от 0.2012 до 0.2021. Максимум `P(tie)` достигается при `d = 0` и равен `tanh(δ/2)`, то есть **10.03–10.07%**. В `train_bt.parquet` ничьих **30.90%**. При почти нулевом `d` для этой доли понадобилось бы `δ ≈ 0.639`. Прогноз `[0.45, 0.45, 0.10]` везде даёт примерно **1.262** log loss на частотах этих данных. Прогноз по частотам классов даёт **1.0972**.

**За четыре эпохи `δ` успел пройти лишь часть пути.** В логе средний `δ` по эпохам рос примерно `0.091 → 0.164 → 0.196 → 0.202`, а log loss продолжал падать. В конфиге Kaggle `δ` стартует с нуля, его LR равен `2e-5`, после разогрева работает cosine decay. Сумма шагов LR за 22 988 обновлений составляет около 0.230. В проверке с одним скаляром, `d = 0`, случайными батчами по 8 примеров с долей ничьих 30.9%, AdamW без weight decay и клиппингом 1.0 тот же график дал `0.092 → 0.168 → 0.203 → 0.208`. Такой бюджет обучения сам по себе воспроизводит траекторию порога. Проверка не восстанавливает историю состояний оптимизатора при resume.

Старт с `δ = 0` подаёт ничьям вероятность `1e-6` из-за `clamp`, и начальный loss для такой строки около 13.82. Проверка формулы в float32 показала, что при `d = 0` градиент по `δ` для строки с ничьей меняется примерно с `−0.5` при `δ = 0` до `−1e5` при `δ = 1e-5`, сразу после выхода из зоны ограничения. Это резкий переход, который стоит учитывать при разборе старта. По имеющимся логам нельзя установить, сыграл ли именно он решающую роль в обучении энкодера.

## Что осталось в разности наград

Прогнали каждый из пяти `best.pt` на 192 случайных строках из его валидационного фолда (`random_state = 41 + fold`). Использовали модель из ноутбука сабмита, локальный токенизатор `microsoft/deberta-v3-base`, 1024 токена и CPU float32. Это выборочная проверка на 960 строках.

| Фолд | Медиана `abs(d)` | Строки с `abs(d) < 1e-5` | AUC по `d` на строках с победителем | AUC по вероятности ничьей |
| --- | ---: | ---: | ---: | ---: |
| 0 | 3.68e-4 | 87 / 192 | 0.617 | 0.578 |
| 1 | 8.29e-6 | 101 / 192 | 0.573 | 0.565 |
| 2 | 1.19e-7 | 191 / 192 | 0.393 | 0.539 |
| 3 | 5.96e-8 | 192 / 192 | 0.598 | 0.604 |
| 4 | 6.40e-3 | 2 / 192 | 0.601 | 0.565 |
| Среднее | — | — | **0.556** | **0.570** |

AUC учитывает порядок оценок и почти не зависит от их масштаба. Поэтому у фолда 3 AUC около 0.60 даже при разнице в наградах порядка `1e-7`. На фолде 2 почти весь разброс `d` даёт одна строка с `abs(d) ≈ 0.267`. На фолде 4 оценки меняются между строками заметно чаще. Степень коллапса отличается от фолда к фолду.

На этих же строках исходный log loss **1.2995**. Если прибавить одно смещение к `log P(tie)` и заново нормировать три вероятности, получается **1.0991**. Для каждого фолда смещение подбирали по предсказаниям на остальных четырёх. Отношение вероятностей A и B при этом сохраняется. Прогноз по одним частотам классов, оценённым так же на остальных четырёх выборках, даёт **1.1023**. Дополнительная подстройка масштаба `d` для выбора A/B довела log loss до **1.0976**. Почти весь разрыв объясняется некалиброванной ничьей, а оставшийся выигрыш от текста на этой выборке небольшой.

**На фолдах 1 и 3 коллапс виден ещё до головы.** На одних и тех же 16 строках валидации фолда 3 (`random_state = 13`) разброс координат CLS между входами, усреднённый по координатам через RMS, упал с **0.0634** у исходной DeBERTa до **1.19e-7** у дообученного энкодера. Норма весов линейной головы при этом **0.512**. На 24 строках фолда 1 с тем же seed разброс упал с **0.0748** до **3.67e-5**. Значит, на этих входах голова уже получала почти одинаковые векторы. Проверка не показывает, на каком шаге обучения это началось и что спровоцировало коллапс. Сохранены только лучшие веса, а в логе нет разброса CLS или `d` по шагам.
